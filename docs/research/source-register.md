# Able research and reference register

This register records inspiration and primary technical references. Product inspiration does not imply code reuse, endorsement, or feature parity. Verify current licenses and Android behavior before implementation.

## Android platform references

| Topic | Primary reference | Product implication |
| --- | --- | --- |
| Adaptive layouts | [Window size classes](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes) | Base layouts on the current window, including resizable and multi-window states. |
| Foreground service types | [Foreground service types](https://developer.android.com/develop/background-work/services/fgs/service-types) | Android 14+ requires an appropriate declared type and permission; Able's monitor is user-started and visibly ongoing. |
| Notification permission | [Notification runtime permission](https://developer.android.com/develop/ui/compose/notifications/notification-permission) | Android 13+ allows starting an FGS without notification permission, but the user may not see its notification in the drawer. |
| Battery cycle count | [BatteryManager.EXTRA_CYCLE_COUNT](https://developer.android.com/reference/android/os/BatteryManager#EXTRA_CYCLE_COUNT) | Optional cycle count in `ACTION_BATTERY_CHANGED` from API 34; no public `BATTERY_PROPERTY_CYCLE_COUNT` constant exists. |
| Battery sysfs attributes | [Android Health HAL 2.1](https://source.android.com/docs/core/perf/health/implementation-2-1) and [Linux power supply class](https://android.googlesource.com/kernel/common/+/e20c980a2bf6/Documentation/power/power_supply_class.txt) | Battery sysfs fields are optional; charge capacities use µAh and may be absent or inaccessible. Show unsupported states and treat derived capacity ratio as an estimate. |
| Android TV input | [Handle TV hardware](https://developer.android.com/training/tv/get-started/hardware) | Many TV devices lack touch and rely on D-pad/remote input; capability-gate hardware tools. |
| TV distribution | [TV app quality](https://developer.android.com/docs/quality-guidelines/tv-app-quality) | Treat TV listing and D-pad usability as a release review target. |
| Per-app language | [App language preferences](https://developer.android.com/guide/topics/resources/app-languages) | Expose Italian/English and follow system by default. |
| User-selected files | [Storage Access Framework](https://developer.android.com/training/data-storage/shared/documents-files) | Use Android document pickers for export/import and user-selected cleanup. |
| Battery properties | [BatteryManager](https://developer.android.com/reference/android/os/BatteryManager) | Read system-reported values; mark unsupported/approximate metrics honestly. |
| Battery health & cycle count | [BatteryManager (API 34+)](https://developer.android.com/reference/android/os/BatteryManager#EXTRA_CYCLE_COUNT) | Public cycle count is an optional Android 14+ battery-broadcast extra; deeper State of Health/manufacturing dates require Shizuku/system access and OEM/HAL support. (Verified 19 Nov 2026). |
| Widget updates | [Advanced app widgets](https://developer.android.com/develop/ui/views/appwidgets/advanced) | Widgets are not a guaranteed real-time surface; use user/event updates and low periodic frequency. |
| Background restrictions | [Doze and App Standby](https://developer.android.com/training/monitoring-device-state/doze-standby) | Avoid global Doze hacks and explain effects of app restrictions. |
| Shortcut pinning | [Create shortcuts](https://developer.android.com/develop/ui/compose/system/shortcuts/creating-shortcuts) | Android/launcher confirmation and launcher-dependent presentation are expected. |
| Package discovery | [Package visibility](https://developer.android.com/training/package-visibility/declaring) and [Play `QUERY_ALL_PACKAGES` policy](https://support.google.com/googleplay/android-developer/answer/10158779) | Able declares `QUERY_ALL_PACKAGES` (ADR-028). Play allows it only when broad visibility is the app's core purpose, requires a Permissions Declaration, and does not list app managers among its examples; decide at release time. Verified 22 Nov 2026. |
| App archiving | [Android 15 features: app archiving](https://developer.android.com/about/versions/15/features#app-archiving) | API 35 adds `PackageInstaller.requestArchive`; unarchive requests go to the responsible installer. Offer only where available (APP-004). Verified 22 Nov 2026. |
| User-selected storage cleanup | [Access documents and files](https://developer.android.com/training/data-storage/shared/documents-files) | `ACTION_OPEN_DOCUMENT_TREE` grants access only to the directory the user selected; Android 11+ restricts some roots. Verified 19 Nov 2026. |
| Screen lock action | [AccessibilityService API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#GLOBAL_ACTION_LOCK_SCREEN) | Android exposes `GLOBAL_ACTION_LOCK_SCREEN` to an enabled accessibility service; enablement remains an explicit user action. Verified 19 Nov 2026. |
| User-mediated app removal | [Intent.ACTION_UNINSTALL_PACKAGE](https://developer.android.com/reference/android/content/Intent#ACTION_UNINSTALL_PACKAGE), [REQUEST_DELETE_PACKAGES](https://developer.android.com/reference/android/Manifest.permission#REQUEST_DELETE_PACKAGES), and [PackageInstaller](https://developer.android.com/reference/android/content/pm/PackageInstaller) | The user-confirmed uninstaller requires the normal `REQUEST_DELETE_PACKAGES` permission and is deprecated from API 29; the replacement `PackageInstaller.uninstall` path is limited to the installer of record or device owners. Able uses the confirmed system UI and verifies package presence on return. Revisit if Able becomes installer-of-record. Verified 19 Nov 2026. |
| Accessibility key filtering | [AccessibilityService.onKeyEvent](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#onKeyEvent(android.view.KeyEvent)) and [FLAG_REQUEST_FILTER_KEY_EVENTS](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo#FLAG_REQUEST_FILTER_KEY_EVENTS) | Key events reach the service before apps; returning true consumes them; requires the filter-key-events capability in metadata. Basis for KEY-001. Power key and screen-off delivery are not documented as available and are not promised. Verified 22 Nov 2026. |
| Accessibility motion events | [AccessibilityService.onMotionEvent](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#onMotionEvent(android.view.MotionEvent)) and [setMotionEventSources](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo#setMotionEventSources(int)) | API 34; events from requested sources "are not sent to the rest of the system", so they cannot observe launcher touches without consuming them. The AOSP observed-sources API (`setObservedMotionEventSources`) is a flagged test API, absent from the public reference. LOCK-003 is feasibility-gated. Verified 22 Nov 2026. |
| Biometric authentication | [Show a biometric authentication dialog](https://developer.android.com/identity/sign-in/biometric-auth) | `BIOMETRIC_STRONG` or `DEVICE_CREDENTIAL` combined is supported on Android 11+; `canAuthenticate()` reports missing credentials; the system prompt is the trusted UI for APPLOCK-001. Verified 22 Nov 2026. |
| Play Accessibility policy | [Use of the AccessibilityService API](https://support.google.com/googleplay/android-developer/answer/10964491) | Non-accessibility tools need an in-app prominent disclosure with consent and a Play Console declaration with video; `isAccessibilityTool` is reserved for disability-focused apps; deterministic rule-based automation is allowed (R-022). Verified 22 Nov 2026. |
| Advanced Protection and accessibility | [Android Developers Blog (Dec 2025)](https://developer.android.com/blog/posts/enhancing-android-security-stop-malware-from-snooping-on-your-app-data) and [Android Authority report](https://www.androidauthority.com/android-17-beta-2-advanced-protection-mode-accessibility-apps-3648860) | With Advanced Protection on, accessibility services of apps that are not accessibility tools are blocked or revoked. Reports place enforcement in Android 17 builds; the owner cited Android 16. Secondary source for the version; recheck the Android 17 release notes (R-023). Checked 22 Nov 2026. |
| User-app restore after `pm uninstall -k --user 0` | Device observation (Android 16 / API 36.1 emulator), 22 Nov 2026 | Data kept but the APK is deleted for user apps, so `cmd package install-existing` fails; system apps restore. Observation, not platform documentation (ADR-033). |
| Accessibility overlay and gesture dispatch | [AccessibilityService reference](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService) | Basis of the Precise home double-tap mode (LOCK-003, ADR-039): accessibility overlays and `dispatchGesture()` (requires `canPerformGestures`). Method-level details were not confirmed from the page on 22 Nov 2026; recheck during T-LOCK-04. |
| Internet settings fallback | [Settings.Panel API](https://developer.android.com/reference/android/provider/Settings.Panel) | Android's internet connectivity panel is a system-owned settings surface; it does not imply direct hotspot credential/control access. Verified 19 Nov 2026. |

## Research rules

- Prefer current official Android documentation for platform behavior and primary project repositories for feature inspiration.
- Record what is confirmed by Android, what was observed on a test device, and what is a product proposal as separate claims.
- Recheck version-sensitive APIs, Play requirements, repository activity, and licenses before implementation/release.
- Do not copy third-party app descriptions or source code into public project documentation. Attribute links and independently specify Able behavior.
