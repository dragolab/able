# Able risk register

Risks are tracked before implementation so feasibility work can shape scope. Ratings are initial qualitative estimates and must be reviewed after prototypes.

| ID | Risk | Impact | Mitigation / evidence needed | Status |
| --- | --- | --- | --- | --- |
| R-001 | Android/OEM limits block reliable double-tap detection or screen locking from every context. | Core gesture feature may not work from lock screen or all launchers. | Prototype on Pixel 8 Pro; document supported contexts; offer tile/shortcut fallback; do not promise universal support. | Open |
| R-002 | Background restrictions or scheduling limitations cause profile triggers to be delayed. | Battery actions may run late or inconsistently. | Compare event-driven APIs and OS behavior on target devices; show last trigger and next evaluation; avoid high-frequency polling. | Open |
| R-003 | Battery monitor consumes power and distorts the idle-drain measurement. | Monitor could worsen the behavior it measures. | Opt-in service, low-frequency sampling, matched on/off test, disclose sampling window and own overhead. | Open |
| R-004 | Current, wattage, deep-sleep, app attribution, or battery health data are missing/inaccurate. | User may make poor battery decisions from false precision. | Display source/coverage/confidence; mark unavailable; compare only valid sessions; avoid causal claims. | Open |
| R-005 | Shizuku availability/API behavior changes across Android versions. | Advanced hotspot/app operations fail or require rework. | Isolate privileged operations behind capability adapters; verify readback; test disconnected and restarted service; keep standard fallback. | Open |
| R-006 | App force-stop/disable/uninstall interrupts alarms, notifications, or system functions. | Lost messages, alarms, health data, or unstable device behavior. | Protected list, impact preview, manual-only freeze/disable, explicit confirmation, action history and recovery. | Mitigated by product rule; validate |
| R-007 | Full package visibility via `QUERY_ALL_PACKAGES` (accepted, ADR-028) conflicts with Google Play policy or privacy expectations. | Play may reject the permission declaration; users may distrust broad access. | Sideloaded builds use the permission; decide the Play declaration at release time (policy restricts it to apps whose core purpose needs it, checked 22 Nov 2026); prepare a Play flavor with narrower visibility if needed; keep the app list on-device and out of crash reports/backups. | Open (release-time decision) |
| R-008 | Malicious/corrupt backup archive triggers path traversal, resource exhaustion, or invalid state. | Data loss or app compromise. | Treat archive as untrusted; size/depth/schema/checksum validation; no executable content; transaction/rollback; adversarial import checks. | Mitigated by requirements; implement |
| R-009 | Hotspot controls vary by device/API and may not be available to ordinary apps. | UI reports unsupported settings or misleading success. | Capability-gate; Shizuku required for direct control (ADR-038); read back state; show unsupported/error with actual value. See R-030. | Open |
| R-010 | Google Play TV eligibility is not achieved despite responsive layout. | TV listing/distribution target fails. | Implement TV launcher entry and D-pad behavior; run current TV quality checklist; treat approval as a release gate. | Open |
| R-011 | V1 scope is too broad for one release and delays a usable core. | Product never reaches a stable first version. | Prioritize battery monitor/profile, core toolbox, config portability, and shared shortcut editor; validate effort and split optional modes if needed. | Open |
| R-012 | Custom launcher behavior changes pinned shortcut icon/label. | Shortcut preview differs from result. | Explain launcher variability, verify pin result where possible, preserve editable definition/history in Able. | Mitigated by requirements; validate |
| R-013 | Optional context signals are unavailable, permission-gated, or misleading on some Android devices. | The user could mistake absent context for evidence or grant access without understanding its purpose. | Keep the baseline independent; explain each source; collect only after explicit opt-in; mark missing values unavailable and apply the same retention/delete rules. | Mitigated by proposal; validate |
| R-014 | Experimental Pixel ToolBox features (AOD modification, Recents injection, screen-off fingerprint, orientation wake) are blocked by modern Android security or private API restrictions. | Features may not be viable across OS updates or non-Pixel devices. | Prioritize technical prototyping on Pixel 8 Pro early in development; make all features strictly opt-in and experimental; fail gracefully with honest unsupported status. | Open (Feasibility gate) |
| R-015 | Android 14+ battery health properties (cycle count, SoH, dates) vary by OEM HAL or return unpopulated values. | Battery health screen may show unavailable fields on some devices. | Distinguish public API vs Shizuku system access; clearly label unpopulated/unsupported values as hardware/OEM limitations; test on Pixel 8 Pro and secondary devices. | Open |
| R-016 | Privileged system toggles (NFC, ADB, Private DNS) require `WRITE_SECURE_SETTINGS` or Shizuku, unavailable to unprivileged apps; shell-side commands such as `svc nfc` can fail under Shizuku (observed on Android 16, 2026-11-23). | Users without ADB/Shizuku cannot toggle directly via Quick Settings tile; a Shizuku command route can crash or break after an update. | Two-tier architecture (ADR-023): direct programmatic toggle when privileged, fallback to opening relevant system settings screen when unprivileged; clear in-app guidance; with Shizuku use the self-grant and in-process calls instead of shell commands (ADR-044, see R-037). | Open |
| R-017 | Physical sensors (accelerometer, magnetometer) drain battery if left running in background or give inaccurate readings due to calibration drift. | Excessive idle battery drain or distorted level/compass orientation. | Strict Compose/lifecycle listener detachment on screen exit (ADR-022); user manual zero-calibration for spirit level; figure-8 calibration flow for compass. | Open |
| R-018 | Google Play may reject the monitor's foreground-service type or require additional disclosure for `specialUse`. | Monitor distribution eligibility may differ between sideloaded APK and Play release. | Treat the current type as a prototype; validate the declaration and policy before a Play release, and retain the explicit user-start/stop flow. | Open |
| R-019 | Bundled UAD-ng data becomes stale or mislabels a package. | A user may disable a needed package based on outdated advice. | Show snapshot commit/date; label missing packages "no information"; removal level is advisory; separate confirmations and the Able archive restore path (ADR-026, APP-004). | Mitigated by requirements; validate |
| R-020 | `pm trim-caches`, `install-existing`, or `pm enable` behave differently across Android versions/OEMs or are restricted for the Shizuku shell. | System-wide cache cleanup or restore fails or frees less space than expected. | Measure free space before/after; read back package state; report failure honestly; validate on Pixel 8 Pro and the tablet reference. | Open |
| R-021 | Lock-screen double-tap detection through Accessibility is blocked by the OS or OEM keyguard. | LOCK-001 lock-screen context may be unsupported on some devices. | Test home and lock-screen contexts separately; report each context's support; keep tile/shortcut fallback (R-001). | Open |
| R-022 | Google Play's Accessibility API policy requires an in-app prominent disclosure, affirmative consent, and a Play Console declaration with video for non-accessibility tools; Able uses the service for LOCK-001/LOCK-003 (including the Precise overlay and gesture dispatch, added 2026-11-22), APPLOCK-001, and KEY-001 (checked 22 Nov 2026). | Play may reject the declaration or require narrower use; Accessibility features could be unavailable in the Play build. | One service with per-feature switches; disclosure before enabling, separate from other disclosures; never set `isAccessibilityTool`; document each use in the declaration; keep deterministic user-configured behavior only; keep tile/shortcut/widget fallbacks; decide at release time with R-007. | Open (release-time decision) |
| R-023 | Android Advanced Protection blocks or revokes accessibility services of apps that are not accessibility tools (owner cites Android 16; current reports place enforcement in Android 17 builds, checked 22 Nov 2026). | Double tap, app lock, and button shortcuts stop working on devices with Advanced Protection; a user could believe protected apps are still locked. | Detect service disabled/revoked state on resume and via Home safety warning (HOME-003); show app lock as unavailable, never as active; explain the cause; test on an Advanced Protection device/emulator when available. | Open |
| R-024 | SystemUI, launcher, or OEM changes alter window/node structure, foreground-window events, or key dispatch. | LOCK-003 empty-space detection misfires or misses (Light and Precise modes); app lock misses a foreground change or prompts in the wrong place; key gestures break after an update. | Capability adapters per behavior; per-context self-test in setup; re-verify after Android/launcher updates; report unsupported instead of guessing; widget/tile fallbacks; test Pixel Launcher and a second launcher. | Open |
| R-025 | APK backups before user-app uninstall (ADR-033) consume storage, and restoring through a shell install session changes or loses installer-of-record attribution. | Storage use grows unnoticed; restored apps may not receive store updates or may show "installed by shell"; split APKs may restore incompletely. | Show size before backup and total in the archive; let the user delete backups; verify all split files and checksums; read back package and version after restore; offer reinstall from the original store; disclose possible attribution change in the confirmation. | Open |
| R-026 | The command shell runs arbitrary user commands with shell (ADB) privileges. | A mistyped or copied command can remove packages, change settings, or delete data; snippets copied from untrusted sources can be harmful. | Never auto-run; dangerous-command warning and confirmation (advisory list); log command and exit status; no shell targets for triggers, tiles, widgets, or key gestures; clear "advanced" labelling and "?" help. | Mitigated by requirements; validate |
| R-027 | No public, non-consuming touchscreen observation API exists for accessibility services at the check date; `setMotionEventSources()` consumes events (checked 22 Nov 2026). | LOCK-003 direct route may be infeasible on all Android versions, leaving only the widget fallback. | Feasibility spike on Pixel 8 Pro (Android 15/16+); never ship a consuming route on the launcher; keep the transparent widget fallback; recheck the SDK reference each release. | Open (Feasibility gate) |
| R-028 | Volume-key double/long-press detection requires holding back the first key event; Android may not allow re-delivering it, and the both-keys gesture overlaps the system accessibility shortcut. | Volume changes feel delayed or a single press is lost on mapped keys; the system accessibility shortcut might trigger. | Map only on user request per key; disclose delay; validate re-delivery; trigger "together" on short press; test with the system accessibility shortcut enabled. | Open |
| R-029 | Background AppOps (`RUN_ANY_IN_BACKGROUND`, `RUN_IN_BACKGROUND`) and standby buckets are hidden platform behavior; OEM battery managers (for example HyperOS) may ignore, override, or reset them after reboot or app update (APP-007, added 2026-11-22). | Users believe an app is restricted when it is not, or a restricted app misses notifications/alarms. | Read back after every change and on screen resume; show actual values and reverted state; warnings in the confirmation; exclude protected/system apps from bulk; batch restore from the log; test on Pixel and Xiaomi Pad 7 (T-APP-07). | Open |
| R-030 | Hotspot control uses system/hidden tethering and SoftAP APIs through Shizuku (ADR-038); methods and parameters change between Android builds or are blocked by carrier/OEM policy. | Hotspot toggle or configuration fails or breaks after an update; risk of crashes or false success. | Runtime feature detection per method; readback of every field; "not supported on this Android build" state; no crash on missing methods; retest on each Android release and the current-API emulator (T-HOT-02); keep the tethering-settings fallback. | Open |
| R-031 | The RAM and processes tool (MEM-001) can be misused or misunderstood as a battery or speed booster; force-stopping or killing apps can stop alarms, notifications, or sync, and apps may restart and use more battery. | Worse battery life, missed alarms/messages, user distrust, or Play policy concerns about misleading claims. | Manual only; confirmation naming consequences; honest copy review (T-MEM-02); no automatic run; protected/launcher/keyboard/Able/core processes excluded; measured values only; BAT-007 keeps automatic RAM cleaning excluded. | Mitigated by requirements; validate |
| R-032 | *Closed 2026-11-23: Precise mode removed (ADR-050).* The Precise home double-tap overlay (ADR-039) intercepts launcher touches and replays them; replay adds latency, may fail for drags, widget scrolling, or multi-touch, and could cover system gesture areas or remain after the launcher loses focus. Owner report 2026-11-23: page swipes are slow; the pass-through window and reduced intercept area trade some double-tap detection for speed. | Launcher feels slow or broken, touches lost, system gestures blocked; double taps right after swipes or on the dock/search bar are missed; Play reviewers may consider it intrusive. | Launcher-only overlay removed on focus loss; exclude system gesture insets, dock, and search bar; pass-through window after swipes and velocity-preserving first-swipe replay (ADR-039 revised); measured delay and page-change rate shown in self-test; Light mode and widget fallbacks; self-test failure blocks enabling; disclosure in setup and the Play declaration (R-022); T-LOCK-04 and T-LOCK-05 on two launchers. | Open (Feasibility gate) |
| R-033 | The repository is public from 2026-11-22 (ADR-011 revised); a commit could expose secrets, signing keys, `local.properties`, private reference notes, `Able_Documentation_Pack.zip`, or release binaries, and published history cannot be fully withdrawn. | Leaked credentials or keys, disclosure of private notes, license/brand confusion. | `.gitignore` covers each excluded path (including `Able_Documentation_Pack.zip` and `.kotlin/`); T-REPO-01 pre-push check and full-history secret scan; `NOTICE.md` reserves names/logos; rotate any credential that was ever committed; release binaries only by separate decision. | Open |
| R-034 | Concurrent profiles with most-restrictive-wins (ADR-005 revised) make it harder to predict which profile changed an app and when a change is reverted. | User confusion; Able reverts a change still needed or leaves a stale restriction. | Pure, unit-tested resolution function; attribution map shown in the UI (source profile per action); revert only Able-attributed changes not required by another active profile; T-PROFILE-05. | Open |
| R-035 | Fake GPS (GPS-003, ADR-045) can be misused to deceive services or people (games, check-ins, delivery or dating apps, workplace attendance); Google Play may restrict or review mock-location apps under its deceptive-behavior or device-abuse policies (policy wording not verified for this case on 2026-11-23). | Harm to third parties, store rejection or removal, reputational damage to Drago Labs. | Honest limits and an explicit "do not use to deceive" statement in setup and help; no claim of undetectability; mock locations stay marked (`Location.isMock()`); no automation can start it; testing-oriented copy and Play listing; verify the current Play policy before a Play release (release-time decision with R-007/R-022); a Play flavor without the tool is possible. | Open (release-time decision) |
| R-036 | OpenStreetMap tiles and osmdroid (ADR-045): the OSMF tile policy forbids bulk/offline prefetch, requires attribution and an identifying User-Agent, and gives no availability guarantee; blocking is possible without notice; osmdroid is archived (2024-11-20) and unmaintained; the map adds Able's first network traffic, exposing the viewed area and IP to the tile server. | Map stops working or Able gets blocked; unpatched library issues; privacy expectations of a "local-first" app are not met. | Comply with the policy (T-GPS-03); fetch only viewed tiles while the map is open; visible attribution; Able-specific User-Agent with contact URL; privacy disclosure in the tool and Settings → Privacy; coordinate entry works offline; abstract the map layer so osmdroid can be replaced (for example MapLibre with another tile provider) by a later decision; monitor osmdroid forks and Android compatibility each release. | Open |
| R-037 | The `WRITE_SECURE_SETTINGS` self-grant (ADR-044) keeps a powerful permission after Shizuku stops, across app updates, until revoked; a bug or a compromised build could change secure settings. | Unintended changes to secure settings (debugging, DNS, NFC, others); user unaware that Able still holds the grant. | Explicit confirmation explaining scope and persistence; grant state and Revoke in the access checklist; documented ADB revoke and uninstall routes; Able writes only the keys of features the user operates and reads every write back; action-log entries for secure-settings writes; never exported; T-SYS-04. | Open |
| R-038 | The floating navigation bar with blur (ADR-042) costs GPU time and may reduce legibility over busy content; it can hide content or actions if padding is wrong. | Jank or battery use while scrolling; low contrast; last list items or buttons hidden under the bar. | Measure frame timing with blur on/off (T-UI-03); light blur radius; opaque fallback surface (also in power-save if needed); WCAG AA checks over worst-case content; content padding from bar height and insets on every screen. | Open |
| R-039 | Optional battery-history export (ADR-046) puts device-usage patterns in a user-managed file that may be shared or stored insecurely; import of crafted history could distort statistics or the baseline. | Privacy exposure; misleading baseline or alerts after import. | Off by default and never preselected; privacy notice; usage history and permissions never exportable; import validation, deduplication, retention warning; baseline recomputed only from valid sessions; adversarial import cases in T-IMPORT-01/T-IMPORT-04. | Mitigated by requirements; validate |
| R-040 | The "Pulse" wordmark uses Google Sans Flex (ADR-027 revised); its license terms for embedding or outlining in an app logo and in a proprietary brand asset were not verified on 2026-11-23. | Brand assets may need a different typeface or license step before release. | Confirm the font license before shipping the wordmark; prefer outlined artwork in the brand assets; keep a fallback typeface decision ready; record the license in the third-party inventory. | Open |
