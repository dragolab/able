## Verification levels

1. **Requirements review:** verify every v1 requirement has an actor flow, acceptance condition, unsupported/error state, and traceability links.
2. **Unit tests (future implementation):** profile precedence/threshold boundaries, interval rate calculations, backup schema parsing/validation, conflict resolution, and capability-state presentation.
3. **Android component tests (future implementation):** permission state, lifecycle/reboot recovery, SAF open/save, notification start/stop, shortcut pin/cancel, app-state readback, and Shizuku disconnect.
4. **Manual end-to-end:** execute the user flows on representative form factors and record evidence, device/OS build, permission state, and result.
5. **Release review:** Android permissions and package visibility, privacy/backup content, Play phone/tablet/TV quality, localization, accessibility, and dependency/license inventory.

## Release exit criteria

- Every `MUST` acceptance criterion passes on its applicable target or has a documented platform limitation approved by the product owner.
- No critical/high-severity issue remains for destructive app actions, configuration import, permission disclosure, or state misreporting.
- Italian and English are complete for all shipped flows.
- TV-specific flows pass D-pad and Play TV usability review before TV distribution is claimed.
- Monitor power impact is measured and published internally; continuous monitoring remains opt-in.
- Public sharing decision taken 2026-11-22 (ADR-011 revised): `LICENSE` (GPLv3) and `NOTICE.md` are present and T-REPO-01 passes before each push; third-party notices (UAD-ng, ACRA, and any reused code) are complete before a GitHub release with binaries.
